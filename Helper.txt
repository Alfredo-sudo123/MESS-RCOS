Instructions to run ESP-IDF installer: 
Option 01: (terminal)
run "eim -help" which will list all options

Option 02: (GUI/recommended)
run "eim" to run the GUI of the ESP-IDF installer

Instructions to run ESP-IDF (On vs-code):

idf.py set-target esp32 // to initialize the project.
idf.py build //to compile and build the project

If the build completes successfully, you will be prompted to run:
idf.py -p PORT flash //Flashes program onto ESP32
(PORT is the ESP32’s serial connection)
idf.py -p PORT monitor //Shows output of ESP32 program while running


Known Issues:
Q#1: finding PORT when needing it to run something like "idf.py -p PORT flash" 

solution:
Run "ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null", it'll return the port which is copied exactly as outputted.
(i.e /dev/ttyUSB0)

Q#2: How do I stop monitoring the program OR reset the program?

solution:
a. To reset the program to line 01, press EN / RESET while plugged in.
b. To stop monitoring the output press "CTRL + C" or "CTRL + ]". NOTE: this will not stop the program


C-MAKE HELPER: (C-MAKE documentation)
https://docs.espressif.com/projects/esp-idf/en/v3.3/api-guides/build-system-cmake.html?highlight=cmakelists%20txt

--> Explanation
    In ESP-IDF, projects expect 2 types of CMakeLists.txt: root level and component level. 
    Every C file requires a component CMakeLists.txt and every project requires 1 overarching CMakeLists.txt.

--> NOTE
    There are automatic C-MAKE generator extensions, although not really required because all component level
    C-MAKE files look identical to an extent because idf_component_register() does the heavy lifting.

1. The root level CMakeLists.txt

Ex:
cmake_minimum_required(VERSION 3.16)
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
project(NAME_OF_FOLDER)

What it does:
compiles and points to ESP-IDF SDK and components. This is also where you would add another path 
to more SDK/components/libraries

2. Component level CMakeLists.txt
Ex:
idf_component_register(
    SRCS "NAME_OF_C_FILE"
    INCLUDE_DIRS "."
    REQUIRES driver
)

What it does it mean:
a. SRCS 
    files to compile
b. INCLUDE_DIRS:
    directories with public headers --> Can #include them && "." = own folder access.
c. PRIV_INCLUDE_DIRS: 
    header directories used only by this component’s own sources.
d. REQUIRES: 
    components whose headers appear in your public headers.
e. PRIV_REQUIRES:
    components you only use inside your .c files



C - File helper (documentation):
1. Inter-Integrated Circuit (I2C) documentation: 
https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/i2c.html#_CPPv423i2c_master_bus_config_t

Relevant documentation to this project: 
a. #include "driver/i2c_master.h" //necessary import

b. Controls serial data line (SDA) and serial clock line (SCL)
(Connects GPIO pins)

c. I2C master controller vs I2C slave controller

d. device vs master I2C bus:
    1d. i2c_master_bus_config_t should be configured in main
    2d. i2c_device_config_t should be configured per sensor

//master struct
i2c_master_bus_config_t bus_cfg = 
{
    .i2c_port = , 
    .sda_io_num = #,
    .scl_io_num = #,
    .clk_source = I2C_CLK_SRC_DEFAULT,
    .glitch_ignore_cnt = $,
    .flags.enable_internal_pullup = true,
};
.i2c_port = sets the I2C port used by the controller

.sda_io_num = sets the GPIO number for the serial data bus (SDA).

.scl_io_num = sets the GPIO number for the serial clock bus (SCL).

.clk_source = selects the source clock for I2C bus. (Can select between options listed in i2c_clock_source_t)

.glitch_ignore_cnt = sets the glitch period of master bus, if the glitch period on the line is less than this value, 
it can be filtered out, typically value is 7

.flags.enable_internal_pullup = enables internal pullups. Note: This is not strong enough to pullup buses 
under high-speed frequency. A suitable external pullup is recommended.

Note: Other inputs to the struct are available including

.intr_priority = sets the priority of the interrupt. If set to 0, 
then the driver will use a interrupt with low or medium priority (priority level may be one of 1, 2 or 3), 
otherwise use the priority indicated by i2c_master_bus_config_t::intr_priority. Please use the number 
form (1, 2, 3) , not the bitmask form ((1<<1), (1<<2), (1<<3)).

.trans_queue_depth = sets the depth of internal transfer queue. Only valid in asynchronous transaction.

.allow_pd = configures if the driver allows the system to power down the peripheral in light sleep mode

NOTE #2: In the case where you need multiple sensors and as such require more than 1 SDA/SCL input, 
you can tether the signals together and the device automatically deals with them. (its possible and common)

// device struct for I2C
i2c_device_config_t cfg = {
    .dev_addr_length = I2C_ADDR_BIT_LEN_7,
    .device_address = addr,
    .scl_speed_hz = 100000,
};

.dev_addr_length = configure the address bit length of the slave device. 
It can be chosen from enumerator I2C_ADDR_BIT_LEN_7 or I2C_ADDR_BIT_LEN_10 (if supported).

.device_address = sets the I2C device raw address. Please parse the device address to this 
member directly. For example, the device address is 0x28, then parse 0x28 to 
i2c_device_config_t::device_address, don't carry a write or read bit.

.scl_speed_hz sets the SCL line frequency of this device.

.scl_wait_us sets the SCL await time (in μs). Usually this value should not be very small 
because slave stretch will happen in pretty long time (It's possible even stretch for 12 ms). 
Set 0 means use default register value.
